# Session Handoff: 2026-11-19b

Self-contained: read only the latest handoff. It supersedes 2026-11-19 (moved to the archive; its tablet spike results are
in note 53 "M4 spike results, tablet runs" and are unchanged).

## Summary

The owner asked for the wrapper ADR (#973), then to use the two connected tablets (SM-T500, SM-X210) as much as
possible. ADR 0015 sets the host route: the `Room` and world stay in the page, native code is only a socket pipe. The
pipe, the Android plugin and UDP game list discovery are built and were run on the real pair. Two real tablets now
find each other in the Lobby and join. There is still no shared farm to play in.

## Completed

- **ADR 0015** (status Proposed, owner to review) and a pointer from ADR 0008. Discovery port 24650 (not Stardew's 24642).
- `src/net/pipe.ts` (`SocketPipe`), `roomhost.ts` (`RoomHost`, browser safe), `pipe-node.ts`, `pipe-capacitor.ts`,
  `announce.ts`; `NodeHost` is now `RoomHost` over `NodePipe` with the tests unchanged.
- `android/.../ElderHostPlugin.java`: WebSocket server, UDP announce, UDP listen with a multicast lock. Registered in
  `MainActivity`. Manifest gains the Wi-Fi state and multicast permissions.
- `SocketTransport` takes a discovery pipe; `LobbyScene` uses `CapacitorPipe` when `Capacitor.isNativePlatform()`.
- `capacitor.config.ts`: `android.allowMixedContent` and `server.cleartext`. Without both, a guest in the app cannot
  open `ws://` to a LAN host (found on the real pair). Recorded in ADR 0015.
- Measured, SM-T500 as host through the plugin (late-game-100, 8 connected: host, 6 desktop guests, SM-X210): tick 0.45
  to 0.54 ms, heap 54 MB, join 390 to 710 ms with 6 at once, round trip p50 157 to 205 ms, max 341 ms. The cap of 8 stands.
- Discovery on the real pair: the SM-X210 Lobby listed the SM-T500's game, the count went 1 to 2 of 9 on a join, a tap on
  the entry joined (host showed 2 connected). A bug fixed on the way: the list was only re-sent when it changed, so the
  Lobby dropped a live game after 6 s (test in `tests/announce.test.ts`).
- Spike tools in `spikes/m4/`: `pipehost.*`, `pipelisten.*`, `deskguests.ts` (README updated). `knip.json` lists the two
  spike entry files.

## Current state

- `npm run check` and `npm run knip` pass. The debug app on both tablets has the plugin.
- Nothing starts a real host from the Host screen yet: `lobbyTransport` is built with no host starter, so `canHost` is
  false. `pipehost.mjs` injects a host into the running app through DevTools instead.
- After a join the Lobby only says "Joined. (The game itself comes with the next build step.)".
- To run the pair: install the DBG app on both (`npm run android:install -- --debug`), `node spikes/m4/pipehost.mjs
  <host serial> late-game-100 8787 <seconds>`, open Play together on the other tablet (screen is 1920 by 1200; the
  button is at about 1500,265 for `adb shell input tap`). Do not start a second `pipehost` while one runs ("already
  listening"); restart the app to clear a stuck listener. Never `pkill -f` a pattern that is in your own command line.
